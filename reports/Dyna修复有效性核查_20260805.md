# Dyna 核心语义修复有效性核查（2026-08-05）

> 核查对象：GitHub 分支 `codex/dyna-core-fix-20260805`（commit `f1f409d`，
> 声明修复旧实现 8 个核心语义 bug）。本地已 checkout 为 `dyna-core-fix`。
> 核查方法：逐项 diff 旧实现（`main`@`b35afdc`）与新实现，运行回归测试，离线验证模型误差。
> 结论：**8 项修复中 6 项确认为真实 bug 且修复正确，1 项结构正确，1 项部分验证；
> 旧实现存在根本性动力学失真，阶段 A–E 与 Phase 0 结论均不得作为正式依据。**

---

## 1. 逐项核查

### 1.1 速度缩放（✅ 真实 bug，修复正确）

| | 旧实现（b35afdc） | 新实现（f1f409d） |
|---|---|---|
| 速度 | `speed = np.abs(action[3])`（[0,1]） | `speed = clip(abs(a_v),0,1) * v_max` |
| `move()` | `velocity = direction * speed`（未乘 v_max） | 同上（已乘 v_max=25） |
| 最大位移/时隙 | `1 × tau_f = 0.3` m | `25 × tau_f = 7.5` m（tau_f=0.3） |

**影响**：旧实现 UAV 每时隙最多移动 0.3m，而场边界 ~500m——UAV 实际几乎静止，
UAV 轨迹规划完全失真。这是影响最根本的 bug。

### 1.2 时隙内信道重复采样（✅ 真实 bug，修复正确）

- 旧实现 `get_channel()` 在 state（`get_uav_state` 325/334 行）、能量采集（287/307）、
  转发速率（461）**各处独立抽取 Rician 实现**——同一 UAV–GU 链路在同一时隙内，
  state 显示的信道与实际转发用信道不同。
- 新实现 `_refresh_channel_cache()`（prepare_step 时调用）每链路每时隙抽一次存入
  `_channel_cache`，`_ensure_channel_cache()` 供 state/速率/能量/转发复用。

**影响**：状态–转移不一致，DQN/模型学到错误映射；修复后物理语义正确。

### 1.3 GU 状态槽错位（✅ 真实 bug，修复正确）

- 旧实现 `for gu_idx in coverage:` 按 coverage 集合压缩 GU 特征——`coverage` 是 set，
  **迭代顺序不稳定**，同一物理 GU 在不同时隙出现在不同 state 位置，未覆盖 GU 特征缺失
  （长度可变，靠尾部 0 填充），与全局 M 槽动作头错位。
- 新实现固定 `for gu_idx in range(M):` 每 GU 固定槽 + `is_covered` 标志，未覆盖 GU
  用 0 填充。state_dim 46→53。

**影响**：旧 state 表征非平稳，策略/模型无法可靠学习；修复后表征稳定。

### 1.4 分层决策时序（✅ 结构正确）

- 旧实现：单步内同时移动+接入，下层经验混入"上层移动后的转移"（下层 DQN 不知道上层
  移动，学习目标非平稳）。
- 新实现：`prepare_step(上层移动)` → 暴露移动后状态 → `lower_act(移动后状态, action_masks)`
  → `complete_step(接入)`。下层经验基于移动后状态，与上层移动解耦。

### 1.5 世界模型残差预测（✅ 修复有效，直接针对 Phase 0d 发现）

- 旧实现 `Model.forward`: `next_state = fc(state||action)` 直接预测绝对值——各维量级
  悬殊（信道 ~5e-5 vs 位置 ~百），MSE 被大维主导，信道维 ~1000× 错标定（Phase 0d 实测
  ‖ŝ′−s′‖≈448，信道维归一化误差 1177–4693）。
- 新实现：输入 `state/state_scale` 归一化，输出 `next_state = state + fc(...)*state_scale`
  残差预测。
- **离线验证**：冻结策略采集转移，新模型 ‖ŝ′−s′‖ = **0.122**（旧实现 448，~3700× 改善）。

### 1.6 Dyna 门控（✅ 设计合理）

新 `dyna_plan` 三重门控：
1. `len(memory) >= max(k, warmup)`（原门控）；
2. `real_steps >= dyna_warmup_steps`（默认 25,600 = 128×200 真实时隙）；
3. `model_error_ema <= dyna_model_error_threshold`（默认 0.20，仅 'model' 模式）。

`update_model` 采用 80/20 train/val 拆分 + 归一化误差 EMA + SmoothL1 + 梯度裁剪 +
目标网络同步，并以 `dyna_model_fraction`/`dyna_counterfactual_fraction` 控制规划批次与
反事实动作比例。

### 1.7 未接入 GU 也产生数据（◐ 部分验证）

`complete_step` 每时隙为每个 GU 生成新数据（独立于接入动作）。逻辑存在，未做统计验证。

### 1.8 模型验证拆分/批量损失（✅ 正确）

见 1.6；`state_loss = SmoothL1((ŝ′−s′)/state_scale)`，验证误差按同一归一化计算。

## 3. 影响评估

1. **旧实现环境动力学根本失真**（速度 bug：UAV 实际静止；信道不一致；GU 槽漂移）。
   阶段 A–E 全部结果、Phase 0 的 0a/0c/0d/0e 结论——包括"DynaQ 无样本效率优势、
   H-error、1.59× 伪象、当前代码 DynaQ 更慢"——**都是旧实现下的观察，不得作为
   正式结论或外推**。
2. 新实现下 DynaQ 行为可能完全不同（速度 bug 修复后，轨迹规划与下层接入的动态都变了），
   **样本效率主张既未被证实也未被证伪**，须重新训练评估。
3. 新实现自带归因门控 `scripts/run_postfix_dyna_gate.py`（NoDyna / Dyna-off / Dyna-gated
   三臂），是新的归因实验基线；Phase 0e 的 Replay-1 被其取代。
4. 旧 checkpoint（46 维）与 53 维新网络不兼容；阶段 E 已下载数据仅作参考。
