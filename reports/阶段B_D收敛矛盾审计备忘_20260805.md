# 阶段 B / 阶段 D 收敛数字矛盾审计备忘（Phase 0a）

> 日期：2026-08-05
> 来源：`待办-dyna归因诊断实验计划.md` Phase 0a
> 目的：解释阶段 B 报告 DynaQ 收敛 330±169 轮 vs 阶段 D K=1 同指标 1282±428 轮的 ~4 倍矛盾；
> 判定哪些历史数字仍可引用。

---

## 结论（一句话）

**330 vs 1282 不是指标实现 bug，也不是 K 值或奖励口径不一致，而是两个训练 commit 之间
`dyna_plan` 的真实代码重写所致。** 阶段 B 用旧版 dyna_plan（批量向量化 + `clip_grad_norm`），
阶段 D 用新版（逐样本循环 + 无裁剪）。K=1 时两版规划损失数学等价，**唯一功能性差异是
dyna_plan 对 DQN 梯度的 clip_grad_norm**（阶段 B 有、阶段 D 无）。

对论文的直接推论：**NoDyna 训练路径在两 commit 间完全未变，因此当前代码下 DynaQ 的
收敛轮数（~1282，阶段 D 数据）不再快于 NoDyna（~525，阶段 B 数据）——"1.59× 加速"
在旧版 clip 代码上成立，在当前代码上可能反转。** 详见 §5。

## 3. 真正的代码差异：dyna_plan 重写

`264c2d7 → bd067e0` 对 Dyna 有实质影响的改动仅三处：

1. **`dyna_warmup` 属性 + 门控**：`max(k, dyna_warmup)`。与旧 `batch_size` 门控等价（§1）。
2. **`update_model` 返回 loss dict**：仅记录用，训练行为不变（已逐行比对主体一致）。
3. **`dyna_plan` 重写**（其余为空白/日志）：

| | 阶段 B（264c2d7） | 阶段 D（bd067e0，即当前代码） |
|---|---|---|
| 结构 | 批量向量化：k 样本一次 GPU 前向 | 逐样本 for 循环，每样本单独前向/backward |
| 世界模型 | `eval()+no_grad` 冻结 | `model_predict()` 同样 eval+no_grad 冻结 |
| 规划损失 | `MSELoss(reduction='sum')` 整批一次 backward | 每样本 `MSELoss()` 累积，逐样本 backward |
| **梯度裁剪** | **`clip_grad_norm_(DQN, clip_norm=1.0)`** | **无裁剪** |
| 门控 | `len(memory) < batch_size(32)` | `len(memory) < max(k, warmup)=32` |

**K=1 时两版规划损失数学等价**（同样的 q_chosen、同样的 target=r_pred+γ·maxQ′(s′)，同样的
逐 GU 求和）。唯一功能性差异 = **DQN 规划梯度的 clip_grad_norm 是否应用**。

## 4. 曲线形状证据：差异真实存在且方向一致

两阶段 reward 曲线（同 metric、同 seed、同 paper_xi）在早期训练动态上真实不同：

| 指标 | 阶段 B DynaQ（旧版 clip） | 阶段 D K=1（当前版无 clip） |
|---|---|---|
| early500 均值 | **522**（逐 seed 251–664） | **367**（逐 seed 321–442） |
| 100 轮滚动峰值位置 | 435–1969（中位 ~1025） | 1926–3252（中位 ~2229） |
| 90% 峰值交叉（收敛轮数） | 190–617（均值 **330**） | 885–1989（均值 **1282**） |
| 末 50 轮 reward | 512.8±105.2 | 480.1±140.4 |

**阶段 B 前 ~300–400 轮就爬到 ~700–790（seed42 ep300=729，seed123 ep400=786），随后波动/衰减；
阶段 D 前 500 轮只有 ~330–440，峰值晚 ~1200 轮。** 这使"90% 峰值交叉"从 330 移到 1282。

补充：**全部阶段 B 曲线（MADDPG/NoDyna/Dyna 均）呈 peak-then-decay**（峰值后衰减 10–54%），
故"90% 峰值"指标测的是"上升途中触及瞬时峰值 90%"，而非"收敛到终值"。该形状特性让
绝对收敛轮数对峰值位置极其敏感——**绝对数字的语义弱，仅同实验内相对比较稳健**。

## 5. 对论文的关键推论（需 Phase 1 验证）

- `HierarchicalNoDynaAgent` 类在两 commit 间**逐字节一致**（已比对）；NoDyna 训练路径
  （update_lower/update_upper）与环境（system_model 仅加 dyna_warmup 配置）未变。
- 因此 **阶段 B 的 NoDyna 收敛（524.6±300.8）对当前代码仍具代表性**；
- 而 DynaQ 因 dyna_plan 重写，当前代码收敛 ≈ 1282（阶段 D K=1）。
- **→ 当前代码下 DynaQ（1282）收敛慢于 NoDyna（525），阶段 B 的"1.59× 加速"
  （330 vs 525）在当前代码上不成立，方向可能反转。**
- 这是**未经验证的跨实验对比**（阶段 B NoDyna vs 阶段 D DynaQ，非配对），仅作方向性警示；
  必须在当前代码上做配对的 DynaQ vs NoDyna（即归因实验三臂）确认。

## 6. 哪些历史数字仍可引用（0a 交付）

### ✅ 仍可引用（需注明口径）
- 阶段 B 的**最终性能**数字（MADDPG 293.7±178.2 / NoDyna 515.0±42.3 / DynaQ 512.8±105.2；
  Ξ 9.8/17.2/17.1 ×10⁻³）——paper_xi 口径、本地原始 JSON 完整可复现、与阶段 C/D 同口径。
  定位为"阶段 B 5-seed 描述性结果"。
- 阶段 B 内部 **DynaQ vs NoDyna 收敛的相对趋势**（4/5 seed 同向、Holm p=0.3125 不显著）——
  同一 benchmark 内部一致；但**必须注明基于旧版 clip dyna_plan**，且不得引绝对值"330 轮收敛"。
- 阶段 D 的 **K=1 vs K=5 相对结论**（K=5 无收益、墙钟 +105.7%）——当前代码、内部一致。
- 阶段 D warm-up 门控结论——单 seed 工程选择，论文仅可描述为"门控规则选出"。

### ❌ 不可直接引用 / 需重做
- **330 vs 1282 的跨实验对比**：代码已变，不可比。
- **"1.59× 加速"作为当前算法的样本效率主张**：基于旧版 clip 代码；当前代码下方向可能反转。
- **任何绝对收敛轮数（330 或 1282）作为"收敛速度"**：回顾性 90% 峰值指标 + 瞬时峰值形状
  使绝对值语义弱；应改用前瞻性"达到固定 Ξ 阈值所需 episode 数"（计划 Phase 0c）。
- **把 warm-up=0/32 当作阶段 B/D 差异归因**：错误，两门控等价。

### ⚠️ 归因实验设计的直接影响
- Phase 1 的 **NoDyna × 5 必须跑**（计划中是"条件跑"）——阶段 B 的 NoDyna 虽是当前代码
  行为，但需要一个当前代码下的**配对**对照才能干净判定 DynaQ vs NoDyna 方向。
- 建议在 Phase 1 增加 **"DynaQ-clip vs DynaQ-noclip"** 对照（或至少记录），直接验证
  §3 的 clip_grad_norm 假设——这是本次审计定位的、当前唯一悬而未决的机制归因。

## 7. 方法局限

1. "clip_grad_norm 移除是 330→1282 的原因"是**基于代码差异的排除法结论**（唯一功能性差异），
   未经 GPU 对照实验验证；机制确认留给 Phase 1。
2. §5 的"方向反转"是跨实验非配对对比，仅作警示，不作定论。
3. 阶段 B 服务器上若存在 `264c2d7` 之后、训练前的未提交改动，无法从 git 检出；
   已用训练日志中的配置项（reward_mode/dyna_k 等）交叉核对，未发现矛盾。
