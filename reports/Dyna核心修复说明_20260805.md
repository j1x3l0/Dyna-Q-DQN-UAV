# Dyna 核心修复说明（2026-08-05）

## 修改后带来的改变

1. 上层速度动作仍输出归一化值，但环境按 `abs(a_v) * v_max` 转为物理速度。单时隙最大位移从错误的 0.3 m 恢复为 7.5 m。
2. 每条 UAV--GU 和 UAV--RBS 链路每个时隙只采样一次；状态、速率、能量采集和转发共用该 realization。
3. 状态改为固定全局 GU 槽，每个槽包含覆盖标志；状态维度从 46 变为 53，解决局部压缩槽与全局动作头错位。
4. 所有 UAV 先同时移动，再统一解决冲突。每时隙至多一个 UAV 转发到 RBS；同一 GU 被多个 UAV 请求时，由缓存信道最强者服务。
5. 分层策略改为“上层移动 -> 生成移动后状态 -> 下层接入决策 -> 完成时隙”。下层经验不再混入未知的上层移动转移。
6. 未接入 GU 也会在每个时隙产生一次新数据，避免缓冲到达过程被接入动作错误控制。
7. 世界模型改为在归一化特征上预测状态增量，训练批次保留 20% 计算验证误差。
8. Dyna 规划必须同时满足真实交互步数和模型验证误差门槛；更新采用批量平均损失、梯度裁剪、目标网络同步，并以受控比例生成反事实动作。

## 默认参数

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `dyna_warmup_steps` | 25,600 | 规划前每个下层智能体需要的真实转移数（128×200） |
| `dyna_model_error_threshold` | 0.20 | 归一化状态 MAE 的 EMA 上限 |
| `dyna_planning_batch_size` | 32 | 规划参考批次 |
| `dyna_model_fraction` | 0.25 | 单次规划使用的模型样本比例 |
| `dyna_counterfactual_fraction` | 0.25 | 尝试策略反事实动作的模型查询比例 |

## 实验口径变化

- 历史阶段 A--E 基于旧环境语义，不能和修复后的训练曲线直接拼接或做显著性结论。
- 旧检查点输入维度为 46，不能加载到新 53 维网络。
- 第一轮应先运行 NoDyna 与 Dyna 的小规模配对验证，确认覆盖率、吞吐、模型验证误差和规划启用比例正常，再启动多种子正式训练。
- 阶段 D 的 `warmup` 参数在新运行中映射为 `warmup * 200` 个真实时隙；旧 JSON 仍保持历史含义，不回写。
