# 分层智能体奖励优化计划

> 创建日期：2026-07-30  
> 状态：**已激活——待阶段 E 正式训练完成、GPU1 空闲时实施**  
> 目标：在不通过数值缩放虚增 reward 的前提下，提高 RBS 实际交付量、论文系统能效
> \(\Xi\) 和最终策略稳定性。

## 1. 启动门槛

以下门槛已于 2026-08-03 满足：K=1/K=5 正式消融完成、原始结果归档、配对显著性检验
与墙钟分析完成、推荐 K=1 冻结并记录代码提交。仍待满足：

- [ ] GPU1 空闲，且没有其他正式训练任务；
- [ ] 将现有 `paper_xi` 实验标记为奖励优化前基线。

阶段 D/E 正式训练运行期间不得修改服务器上的奖励、环境、智能体或训练脚本。

## 2. 当前基线与问题

当前正式口径为：

- 上层奖励：`paper_xi × reward_scale − collision_penalty`；
- 下层奖励：`data_received − eta1 × harvested_energy_total`；
- 最终论文指标：RBS 交付数据 / UAV 总能耗；
- 核心基线：Hier-NoDyna；
- 增量方法：Hier-DynaQ。

主要风险是下层倾向于优化 GU→UAV 数据收集，而最终目标要求 UAV→RBS 完成交付。
即使上下层奖励已经分离，两层的局部目标仍可能不完全一致，导致缓冲区积压、无效接入
或收集了当前轨迹下难以转发的数据。

## 3. 优化原则

1. 不修改信道、能量采集和吞吐量等物理公式；
2. 不把增大 `reward_scale` 当作性能提升；
3. 所有候选奖励必须同时报告 reward、\(\Xi\)、RBS 交付量、能耗、缓冲区和碰撞；
4. 每次只改变一个奖励因素，避免无法归因；
5. NoDyna 与 DynaQ 使用完全相同的候选奖励；
6. 新奖励结果不得与旧 `ee_ratio` 或当前 `paper_xi` 结果直接混合统计；
7. 保留原奖励模式，新增模式必须通过显式参数选择。

## 4. 候选方案

### R0：当前基线

\[
r_{\mathrm{lower}} =
D_{\mathrm{accepted}}-\eta_1 E_{\mathrm{harvested}}
\]

用途：作为所有奖励优化实验的固定对照。

### R1：缓冲区拥塞感知

\[
r_{\mathrm{lower}} =
D_{\mathrm{accepted}}
-\lambda_b B_{\mathrm{ratio}}
-\lambda_d D_{\mathrm{dropped}}
\]

其中 \(B_{\mathrm{ratio}}\) 为 UAV 缓冲区占用率，\(D_{\mathrm{dropped}}\) 为因缓冲区不足
未能接收的数据。该方案用于减少无效收集和缓冲区堆积。

### R2：转发贡献感知

\[
r_{\mathrm{lower}} =
\alpha D_{\mathrm{accepted}}
+\beta D_{\mathrm{forwarded}}
-\lambda_b B_{\mathrm{ratio}}
-\lambda_d D_{\mathrm{dropped}}
\]

该方案把下层接入决策与最终 RBS 交付建立直接联系。必须确认
\(D_{\mathrm{forwarded}}\) 的归因方式不会使用未来不可观测信息。

### R3：势函数奖励塑形

\[
r' = r + \gamma\Phi(s')-\Phi(s)
\]

候选势函数由“可转发缓冲数据、到 RBS 的信道质量、缓冲区拥塞”构成。该方案优先用于
改善学习过程，同时尽量保持原优化目标的最优策略不变。

### R4：差分奖励（高成本候选）

\[
r_i = \Xi_{\mathrm{actual}}-\Xi_{\mathrm{without\ action}\ i}
\]

通过反事实环境评估单个接入决策的边际贡献。只有 R1–R3 无法解决信用分配问题时再做，
因为计算成本和实现复杂度较高。

## 5. 实施顺序

### 阶段 RO-A：指标和数据流准备

只增加诊断，不改变奖励：

- 保存每轮平均/最大缓冲区占用率；
- 保存丢弃数据量；
- 保存 GU→UAV 接收量和 UAV→RBS 交付量；
- 保存转发/接收比；
- 保存上下层奖励各组成项；
- 验证各组成项相加后等于实际训练奖励；
- 更新 README 参数表和知识地图。

通过条件：1–5 episode 冒烟测试中所有指标有限、无 NaN、单位和聚合口径正确。

### 阶段 RO-B：单因素门控

固定阶段 D 推荐 K，使用 seed 42：

| 方案 | 轮数 | 用途 |
|---|---:|---|
| R0 | 500–1000 | 同代码基线 |
| R1 | 500–1000 | 验证缓冲区惩罚 |
| R2 | 500–1000 | 验证转发贡献 |
| R3 | 500–1000 | 验证势函数塑形 |

候选方案必须同时满足：

- 最终 \(\Xi\) 不低于 R0；
- RBS 交付量提高，或达到相同交付量时能耗降低；
- 丢弃数据和终局缓冲区不恶化；
- 没有通过明显增加碰撞或违规动作换取收益；
- 学习曲线未出现持续发散。

只保留最多两个候选进入下一阶段。

### 阶段 RO-C：三种子验证

候选方案与 R0 使用 seeds 42、123、2026，运行统一早停训练。比较：

- 实际停止点前最后 50 轮 reward；
- 最终 \(\Xi\)；
- RBS 交付量、总能耗；
- 缓冲区占用和丢弃量；
- 收敛轮数及墙钟时间；
- 配对 seed 改善方向是否一致。

只有至少 2/3 seeds 在 \(\Xi\) 上改善，且均值改善不依赖单个异常 seed，才进入正式实验。

### 阶段 RO-D：五种子正式实验

冻结代码后，对 R0 和胜出奖励执行相同的 5 个配对 seeds。NoDyna 与 DynaQ 都必须运行，
以区分“奖励优化收益”和“Dyna规划收益”：

| 算法 | 奖励 |
|---|---|
| Hier-NoDyna | R0 |
| Hier-NoDyna | 最优候选 |
| Hier-DynaQ | R0 |
| Hier-DynaQ | 最优候选 |

正式报告采用精确配对检验、效应量、95% bootstrap 区间和多重比较校正。

## 6. 参数选择边界

门控阶段只允许小规模、预先声明的权重集合：

- \(\lambda_b\)：低、中、高三个等级；
- \(\lambda_d\)：0 或一个固定惩罚等级；
- \(\alpha\) 固定为 1；
- \(\beta\)：低、中两个等级；
- 势函数整体权重只比较两个等级。

权重应先依据各组成项的自然数量级归一化。禁止用正式 5-seed 测试集反复调参。

## 7. 成功标准

奖励优化成功至少满足：

1. 最终 \(\Xi\) 相对同算法 R0 有稳定改善；
2. 改善来自交付量增加或能耗下降，而不是 reward 缩放；
3. 多数配对 seeds 改善方向一致；
4. 缓冲区和丢弃数据指标能够解释性能变化；
5. NoDyna 与 DynaQ 的收益可分离归因；
6. Case 2 至少验证最终胜出方案一次。

若只改善训练速度、不改善最终 \(\Xi\)，应归类为样本效率优化，不声称最终性能提升。

## 8. 停止条件

满足任一条件则停止扩大奖励搜索：

- R1–R3 均不能在三种子验证中稳定超过 R0；
- 提升只出现在 reward，实际 \(\Xi\) 没有提高；
- 提升依赖明显增加碰撞、能耗或数据丢弃；
- 权重对不同 seeds 极端敏感；
- 新奖励使论文创新主线从 Dyna-Q 完全偏移且实验成本不可控。

此时保留 `paper_xi` 作为最终奖励，并把信用分配列为未来工作。
